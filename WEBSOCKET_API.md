# Документация по WebSocket API для LiveEdit

## URL подключения

```
ws(s)://<host>:8080/ws/editor
```

- **Аутентификация:**
  - Альтернатива (менее безопасно): через query-параметр `?token=...`.
  - Для production используйте только WSS (WebSocket Secure)!

---

## Протокол сообщений

Каждое сообщение — JSON-объект с полями:
- `type`: строка, тип события (`init`, `edit`, `cursor`, `undo`, `redo`)
- `data`: объект с данными для этого события


### 2. Инициализация сессии
**Клиент → Сервер:**
```json
{ "type": "init", "data": { "documentId": 123 } }
```
**Сервер → Клиент:**
```json
{ "type": "init", "data": { "documentId": 123, "content": "Текущее содержимое документа" } }
```

### 3. Операция редактирования
**Клиент → Сервер:**
```json
{ "type": "edit", "data": { "position": 5, "text": "abc", "isInsert": true } }
```
**Сервер → Клиент (broadcast всем):**
```json
{ "type": "edit", "data": { "clientId": "42", "position": 5, "text": "abc", "isInsert": true, "operationId": "uuid" } }
```

### 4. Курсор
**Клиент → Сервер:**
```json
{ "type": "cursor", "data": { "position": 7 } }
```
**Сервер → Клиент (broadcast всем):**
```json
{ "type": "cursor", "data": { "clientId": "42", "position": 7 } }
```

### 5. Undo / Redo
**Клиент → Сервер:**
```json
{ "type": "undo" }
```
или
```json
{ "type": "redo" }
```
**Сервер → Клиент (broadcast всем):**
```json
{ "type": "undo", "data": { "clientId": "42" } }
```
или
```json
{ "type": "redo", "data": { "clientId": "42" } }
```

---

## Общие принципы работы
- Все сообщения должны содержать поле `type`.
- Для событий edit/cursor/undo/redo сервер рассылает изменения всем участникам документа.
- Аутентификация обязательна (через query).
- Если соединение разорвано — фронт должен переподключиться и повторить handshake/init.
- Для каждого документа поддерживается отдельная сессия.

# Рекомендации по логике фронтенда

## 1. REST API (Swagger)
- Используйте REST для:
  - Аутентификации (login/register/refresh)
  - Получения/создания/удаления документов
  - Получения профиля пользователя
  - Управления доступом, инвайтами, ролями
  - Сохранения документа (если нужно явно сохранить)
- Все эндпоинты и схемы — в Swagger (combined.json)

## 2. WebSocket
- Используйте WebSocket для:
  - Реального времени: совместное редактирование, курсоры, undo/redo
  - Получения изменений от других пользователей
  - Отправки своих изменений (edit/cursor/undo/redo)
- После открытия соединения:
  1. Отправьте `init` с documentId
  2. Получите текущее содержимое документа
  3. Обрабатывайте входящие события (edit/cursor/undo/redo) и применяйте их к редактору

## 3. Сценарии работы
- Открытие документа:
  - Получить список документов через REST
  - Открыть WebSocket, пройти handshake, отправить init
  - Получить содержимое, отобразить в редакторе
- Редактирование:
  - При каждом изменении текста отправлять `edit` через WebSocket
  - При перемещении курсора — отправлять `cursor`
  - Для undo/redo — отправлять соответствующее событие
- Сохранение:
  - Автосохранение происходит на сервере (dirty-флаг)
  - Можно явно вызвать REST PATCH для сохранения (например, по кнопке)
- При потере соединения — переподключиться, повторить handshake/init, восстановить состояние

## 4. Безопасность
- Всегда используйте HTTPS/WSS
- Не храните JWT в cookie
